# 一、配置结构与职责
测试配置从单一大文件收敛为根清单及六份目录清单。根控制全局计划、必需策略、预算、成本上限及禁用实机草案；局部文件只维护目录、文件和方法差异。没有差异的目录不建立空配置。

执行器静态发现普通测试方法，生成路径标识和计划名单；目录继承到文件与方法，错误字段和失效引用显式报错。测试选择、资源授权与结果放行仍分别处理，来源链和配置指纹随执行证据保存。源包结构和产品行为保持原样。

# 二、实施与验证
保留迁移前快照，对原有方法元数据、计划成员、顺序、预算和实机禁用状态做等价比对。新增配置树自检，随后执行完整离线回归和只读准备计划。实际数量、指纹与限制只在运行记录维护，不据配置缩减宣称产品能力提高。

# 三、后续边界
当前只支持现有的类内直接定义测试方法。继承或动态生成测试需要先扩展发现合同。配置树试验结束后停止实施，产品界面和功能方案仍待重新规划，未提交或推送。
