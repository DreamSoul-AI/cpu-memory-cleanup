用户反馈桌面圆环过小、视觉比例异常，网页效果正常。本轮只修正桌面呈现，不改网页或Package动作。

# 一、原因与调整
前轮将桌面Canvas固定为156像素，中心字体仍使用40点；Tk字体会随显示换算放大，画布却不随之变化，主窗增高并不能解决圆环内部比例。此前只检查窗口请求尺寸不足以覆盖这一问题。

圆环改为96 DPI下220像素基准，窗口宽度基准460像素；由Tk每英寸像素统一换算圆环、线宽、中心像素字号与主要内容换行宽度。中心字体使用负像素字号，明确与圆环几何对应。保留实时刷新、绿色按钮、最近结果和详情入口。用户需要关闭旧进程重新打开CMD入口，既有窗口不热重载。

# 二、验证边界
新增150%圆环与中心字号一致缩放的测试，受影响44项通过；隐藏真实Tk测量75%、100%及未知文字的容纳宽度，两个缩放档均通过。详细数值、原失败与限制见 [运行记录](<../运行记录 Run Record/2026-10-31 桌面圆环比例修正.md>)。没有执行真实系统采样或清理，也没有用窗口总高度通过替代原生可见视觉验收。

# 三、圆环边缘平滑
用户进一步反馈边缘不光滑。本次将Tk直接圆弧改为标准库生成像素覆盖图像，保持窗口布局和交互不变。就近增加ring.py负责纯像素渲染，desktop仅负责PhotoImage装配；缓存尺寸几何及最近呈现值，避免静止状态重复绘制。没有引入Pillow、新窗口框架或系统图形接口。

本次定位时未找到用户已打开的桌面窗口，未声称看到了用户所指截图。随后启动限时自动关闭的合成预览，但Computer Use截图返回空白，故原生观感不标记通过。Tk解码、渲染方向与边缘混色已有受控证据，详见对应运行记录。用户关闭旧窗口后重新打开源码CMD入口可试用修改。
