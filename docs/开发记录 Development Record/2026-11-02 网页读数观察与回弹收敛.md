# 一、设计与实现
先在 [开发计划第十四章](<../开发计划 Development Plan CPU 内存清理.md#十四360式过程与结果收敛>) 固定需求与验收，再更新 [架构第十七章](<../架构设计 Architecture Design CPU 内存清理.md#十七业务完成与显示收束分离>)、[代码结构第十九章](<../代码结构设计 Code Structure Design CPU 内存清理.md#十九读数观察与网页反馈收敛>)。同时修正这些文档旧章节中“业务返回即回弹、锁定旧目标”的冲突描述。

- 业务完成继续立即发布快照结果、恢复按钮；显示层不拥有任务完成权，不派发或重试清理。
- 圆环沿原三秒线性归零，未完成时在零位等候。业务返回后，用持续取得的实际样本观察读数；至少三秒、满足短窗口趋缓或到八秒上限后回弹。
- 回弹过程中以当前显示位置平滑转向新读数，最终接回最新值。重复时间戳不累计观察次数，旧响应不覆盖更新值；没有新读数时有界退出。
- 主区保留实际占用、容量、绿色按钮和简短整理结果。动效开关收入详情与设置；逐进程原始错误、完整前后值和Run保持可查。
