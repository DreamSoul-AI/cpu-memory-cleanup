# 一、规划方向

在既有桌面交互之外，规划供外部 Agent 调用的内存工具能力：一次内存状态、一次工作集整理、原运行记录回看。人与机器调用共用功能核心，不另建清理引擎。

首期采用本地 CLI 与 JSON，复用现有非交互入口、动作报告和离线回看。MCP 作为具体宿主需要时的后续适配；持续资源管理 Agent、自动巡检和干预仍独立，不成为工具化的前置条件。

# 三、后续确认的包优先顺序

后续明确先建设可直接使用的 package，再以薄 CLI 提供 tool 入口，最后接入前端。当前计划已据此修订为包公共合同、包实现、CLI/Tool、前端、条件性 MCP 与独立实机验收六个阶段。初次规划中的“CLI 优先”不再是当前实施顺序。

确认已有可安装包与模块结构，当前缺口是包公共入口和可复用装配。目标在现有结构内增加 `api.py` 薄公共入口，优先公开创建工厂并复用 Application；不另外建立 SDK 状态或执行引擎。直接调用返回对象，CLI 转为 JSON，前端负责呈现。前端与 CLI 并列依赖包，前端不必启动 CLI 子进程。

架构补充语言无关的能力复用边界与接入关系，代码结构设计补充目标入口、依赖、当前差距和验证位置，README 同步当前状态。本阶段仍未创建目标源码或运行测试，既有 UI 实现继续保留。
