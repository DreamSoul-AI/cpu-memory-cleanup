# 一、决定与范围
用户在P1/P2真实探索后明确要求尽量复刻360，不继续扩展其他策略。本轮选择所查明的逐进程SetProcessWorkingSetSize(-1,-1)作为正式一键整理路径，采用依据是产品目标，不把不满足起点容差的单次测量说成性能胜出。设计先更新架构第十六章、代码结构设计第十八章与开发计划第十三章，再实现。

只复用已查明的内存工作集机制及现有产品交互；不采用条件性终止软件分支，不新增文件缓存、Standby组合或其他实验路线。没有复制第三方源码、二进制或资源到产品。

# 二、实现变化
- 正式操作系统装配对系统范围和单目标工作集选择SetProcessWorkingSetSize，Package、CLI/Tool、网页、桌面沿用原入口。内部显式对照仍可选择原NT全局和EmptyWorkingSet单目标，Standby保持独立原生和权限流程
- 系统范围一次请求在原互斥内枚举进程，对当前句柄取得并核对身份，逐项执行一次两个SIZE_T(-1)的裁剪并关闭句柄。不可访问对象跳过，原生失败记录后继续，调用未知或关闭未确认停止且不重试。该方式不调整令牌特权、不结束进程、不循环清到零
- 记录在原system范围动作内增量保存native_method与process_sweep，包含访问覆盖、成功/失败/未知数及最多1024条逐项结果，超过部分另列明细遗漏数。一次用户请求不再等同一个原生调用；原生计时对每项单独取得再求和，枚举、句柄与身份检查另计
- 共用呈现器在真实容量结果后附成功、跳过和失败数。没有修改网页资源、桌面控件或动效。报告完成后立即发布，后台读数继续独立刷新

产品与测试提交9ad215a。新增测试沿现有镜像与局部manifest登记，覆盖正式装配、一次遍历、参数、失败口径、句柄收尾、计时与Package/网页/离线回看。实际运行证据见 [运行记录](<../运行记录 Run Record/2026-11-02 360逐进程工作集产品接入.md>)。
