首轮本地实现曾把脚本放入技能包；按本次确认已迁回产品仓库，并逐文件核对后移除 Knowledge 与当前安装技能内的脚本副本。重新生成纯说明技能 ZIP，修正元数据为 UTF-8。历史安装验证保留原路径含义，职责分离后另外核对产品脚本的静态初始化与新技能包一致性。

# 五、使用与开发记录的边界修正

普通 Skill 调用不依赖源码检出或项目 docs，不另写开发 Markdown。产品初始化脚本原本按自身目录与用户数据位置工作，本次将其作为用户安装副本验证，Knowledge 同步调用与结果保存说明。工具所需 JSON 留在用户数据目录；上一轮普通调用误生成的仓库 Markdown 与附加回执移到已有用户运行目录保存，不删除实际证据。今后只有明确的开发、测试或归档任务才写项目资料。

# 六、从原生代码取消普通调用的自动记录

独立测试虽然没有改仓库 Markdown，仍由功能层三次强制 save 和一次 save_timing 创建 JSON，说明前一阶段的“必要记录”解释没有满足实际需求。本次把保存目标改为可选，普通工具调用只返回内存中的 Report；已有显式目录 API 和网页/桌面继续保存，保存失败前置阻断保留。没有另写清理实现，没有临时写后删除。

CLI 默认无保存路径，--no-record 与 --output-dir 互斥，静态目录声明 stdout_only 能力。Skill 普通维护显式使用 --no-record，旧原生程序缺少能力时停止，不能用删参数或自动保存回看绕过。初始化不再返回默认运行记录目录。安装完整性回执与操作历史分开，旧操作文件不自动删除。

新增 6 项 CLI 隔离回归，涵盖全局、单目标、批次、partial、参数互斥及静态能力。完整质量脚本通过：默认 35 项 Rust、开发配置 43 项 Rust、34 项网页测试与 Clippy。显式保存的旧测试及 HTTP 保存/收尾测试通过。新构建 ecb09dcbd04683e1 真实只读及参数保护检查未产生工作目录文件或新运行目录，未执行真实整理。候选单独安装在用户 local-builds，正式已发布程序未覆盖；Skill、ZIP 与本机安装同步，尚未提交、推送或发布。
