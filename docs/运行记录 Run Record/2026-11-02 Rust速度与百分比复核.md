# 三、360与显示源码复核
360该循环是Toolhelp→OpenProcess(SET_QUOTA)→SetProcessWorkingSetSize(-1,-1)→CloseHandle→下一项，无已见并发。当前 Rust 用EnumProcesses、QUERY_LIMITED_INFORMATION加SET_QUOTA、一次创建身份读取和同一裁剪函数。360循环未核对每项裁剪BOOL，本项目保留覆盖和错误；两者“函数返回完成”含义不能直接等同。全局最小权限是候选，不能承诺省几秒，也不能削弱明确目标合同。

网页源码可核对的问题为：读取后等待1000毫秒，过渡400毫秒，剩余时段停住；细条JS逐帧width与CSS 0.4秒transition叠加；动效结束直接paint最新值可能形成接回跳变；整数与300毫秒大幅回弹可导致每帧跨多个百分点；主操作开始/结束无条件renderRows，已读且折叠的列表也重建。渐变、阴影及DOM写入的实际绘制代价仍未测，不从代码存在直接认定掉帧根因。

原浏览器记录点击至结果3360.1毫秒、下降约762.7毫秒、视觉结束4441.2毫秒。报告120毫秒轮询的时机与约101.2毫秒残差一致，但该差额还含受理时点、传输和调度，不能当作准确纯网络时长。web_timing来自同一Run的browser-report.json，未封入磁盘report.json，首次分析读取该字段失败后改读原浏览器回执，没有修改原件或补造时长。最大RAF间隔18.6毫秒不覆盖所有页面状态，也不能否定停走节奏。
