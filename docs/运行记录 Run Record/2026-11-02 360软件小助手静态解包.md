# 三、局部清理例程的机器码核验
SMLCore.dll的SetProcessWorkingSetSize导入地址为0x101bd154，按文件原始首选基址0x10000000解释。文件偏移563498处为对应的间接调用，VA为0x1008a52a，RVA为0x8a52a。这里只是静态地址，不是读取了运行进程中的地址。

对文件偏移563380至563589的片段，核对导入表及实参字节，确认以下顺序：

1. Process32FirstW取得枚举中的进程项
2. 使用进程项中的PID调用OpenProcess，访问位为0x100，继承标志为0
3. 句柄非空时，传入该句柄和两个-1调用SetProcessWorkingSetSize，随后CloseHandle
4. Process32NextW成功后向前回跳，继续该处理

verify-extraction.py对以上调用顺序、两个-1参数及回跳字节做确定性核验。SetProcessWorkingSetSize的公开契约将两个SIZE_T(-1)解释为尽可能移出目标工作集页，而非任意数据压缩。[Microsoft 接口说明](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-setprocessworkingsetsize)

SoftMgrLite.exe里另外找到九处完整的GetCurrentProcess→SetProcessWorkingSetSize(自身句柄,-1,-1)字节模式。它们与SMLCore.dll的枚举路径分开登记，不能把自身裁剪误认成全机加速。这些是静态引用数，没有在本轮实际调用接口。

本机LIEF提供disassemble方法，但当前构建提示反汇编器不可用，返回空结果。本轮没有声称取得自动反汇编全文，而是使用导入地址交叉引用和局部x86参数字节核验。尚未确认按钮事件到该例程的调用链、其他分支、排除对象、错误汇总、动态权限和速度，不将上述局部分析升级为完整还原360实现。
