下降0xdcf9c将当前显示起点除25，0xdcfa4传30毫秒，定时器1逐步减去该步长，故名义750毫秒。本项目当前750毫秒线性下降与该名义值一致。相同时间内起点不同，绝对百分比下降速度不同，例如40%起点约53.3个百分点/秒，60%起点约80个百分点/秒，不能用固定百分点速度理解。

# 三、回弹目标数据流
窗口普通分支+0x1c8为0、控件活动+0x144非0时进入动效数据分支。保存全局比例a从0x7a1020复制到0x7a101c。0xd9875提供器返回新百分比并除100，0xd9885比较旧a与新b，test ah,0x41后jne进入a≤b分支。

| 输入关系 | 路径与保存目标 |
| --- | --- |
| a≤b | 0xd98d6加载常量100，经0xd98b2浮点栈交换，保存的仍是a |
| a>b | 0xd9890起再次读取提供器，归一化并经0xd98b2，0xd98bd保存该次新值 |

随后0xd990f从保存全局值写入目标+0x138。假设同分支第二次读取未变化，该更新等效min(a,b)。离线栈追踪40→35得到35、35→26得到26、26→35仍26、26→26仍26。该表是静态指令语义推导，不是360运行实测。局部辅助百分比/提示计算未据此宣布全部恢复。

动效结束清+0x144，后续普通分支0xd9835至0xd9859直接使用提供器当前值，因此不能推断360永远锁在较低占用。其低目标属于单次视觉周期，不能代表当前系统读数或长期收益。

# 四、本项目的原因与优化建议
当前CleanupFlow.update在returning时接受任何新目标，保留截止时刻。新读数高则终点高，新读数低则终点低，晚到时速度也可能变化。这解释了可从实现确认的差别，但用户本次高/低现象没有提供对应data-flow，不能把所有现象定位成同一个故障。上轮实测27.06→26.55只证明那次时间线，不能保证每次相同终点。

建议下一轮比较单周期视觉目标只下调、结束连续交回实时，以及剩余速度平滑的最小候选。原始实际读数和结果仍即时，不能把视觉最低值称为当前占用；不跨周期保存低值，不固定26%。下降先保持已有750毫秒基线，先量分段时长再改参数。阶段文字暂留，产品收敛时去掉归零动效等技术词。
