**主机内存维护与工具实例回收 架构设计**
更新日期：2026年10月21日。状态：基于 DreamSoul 资料形成的目标设计，部分能力已实现，部分依赖宿主支持。依据与历史结果见 [通用调研](通用调研.md)。

# 一、目标与设计依据
## （一）目标
让使用者能够区分主机内存压力、页面迁移与工具实例生命周期，取得可以追溯的观测结果，并在有授权和完整契约时验证资源释放。一次动作是否执行、机制是否完整成功、收益是否成立分别表达。

设计沿用 DreamSoul 回收报告提出的所有权、保存和宿主协调边界，保留当前 Python 标准库实现，不新增外部服务、数据库、插件框架或按 PID 结束进程的机制。研究依据见通用调研第三章，飞书排版与调研规范见其参考资料 R01。
## （二）范围与实施状态
| **能力** | **状态** | **本轮范围** |
| --- | --- | --- |
| 主机一次性读取、有界采样、离线统计 | 已有实现 | 核对职责与数据口径，未实际采样 |
| 显式 Windows 释放、桌面按钮、A/B | 已有实现，有已知失败处理缺口 | 说明原行为和修复要求，未改变逻辑或运行 |
| 连接级实例所有权与状态报告 | 宿主能力未取得，本仓库未实现 | 明确最小契约与未知状态 |
| 宿主正常释放及重建验证 | 条件式目标设计 | 没有可执行关闭名单，不连接内部 IPC |

不修改审批策略、应用配置、系统设置、页面文件或注册表，不结束进程、不停服务、不自动提权。当前先不运行清理，真实验证需后续明确指令。

# 二、系统边界与职责
## （一）逻辑结构
| **逻辑层** | **现有载体或责任方** | **输入与输出** | **约束** |
| --- | --- | --- | --- |
| 使用入口 | `__main__.py`、`desktop_ui.py`、启动脚本 | 用户模式选择 → 报告或显式动作 | 默认只读，打开界面不释放 |
| 主机观察 | `windows.py`、`tree-series.ps1` | PSAPI/PDH/CIM → 时间标记与指标 | 不推断连接所有权 |
| 离线分析 | `analysis.py`、`pressure.py`、`follow.py`、`treesummary.py` | JSONL → 统计、压力与残差 | 不调用释放，不把缺失当零 |
| Windows 动作 | `release.py`、`privcheck.py`、`privscope.py` | 明确机制 → 逐项调用与状态 | 只操作已列出的全局内存列表 |
| 对照验证 | `abprotocol.py`、`abcompare.py` | 计划、窗口和动作记录 → 有条件判定 | 完整实验、失败窗口和历史观察分开 |
| 工具连接生命周期 | 创建并持有 transport 的宿主 | 使用者、请求和保存状态 → 正常关闭确认 | 属于外部宿主，本仓库没有该控制能力 |

这些是职责分层，不表示新增独立进程。现有 CLI、GUI 和分析模块保持同一包结构。宿主未提供契约前，不新增空适配层或占位释放按钮。
## （二）资源与数据所有权
| **对象** | **权威持有方** | **本项目的责任** |
| --- | --- | --- |
| 物理内存、工作集、提交量 | Windows | 采集、解释、显式调用并保留结果 |
| 工具连接、引用、执行队列 | 工具宿主 | 只接受宿主有版本和代次的证据，不由父 PID 推造 |
| 浏览器控制权、内存对象、待返回结果 | 对应工具实例及业务使用者 | 关闭前由宿主按契约保存或确认可丢弃 |
| 观测与验证文件 | 当前运行的输出目录 | 记录真实数据与失败，不自动覆盖或重建旧数据 |
| DreamSoul 规范、报告与历史证据 | 关联的本地资料目录 | 通过原路径引用，保留日期，不复制成另一研究库 |

# 三、现有执行路径与交互
## （一）只读路径
CLI 解析模式后调用主机查询或离线分析，再输出报告。`--sample` 必须有间隔、次数与保留输出方式，默认不排名进程。`--pressure-follow` 只读取其它程序已写入的日志，到轮数停止，不自行采样。

GUI 使用后台线程读取内存指标，通过队列回到 Tk 线程显示。物理占用比例为 `(总量−可用量)/总量`，不是综合健康评分。读取失败显示错误，不能保留旧数值并当成新的成功读数。
## （二）Windows 显式动作路径
现有顺序为参数选择 → 特权只读检查 → 前快照 → 特权作用域 → NT 调用 → 恢复特权 → 后快照 → 返回结果。`perform_release` 为 CLI 与 GUI 的共同入口。

CLI `--release` 默认选择 `both`，也可选择 `working-set` 或 `standby`。桌面界面和控制台显式 `release` 参数只调用工作集释放。GUI 打开和控制台无参数运行都只读。这里只记录现有契约，不把命令说明当作本轮执行授权。

调用使用 `NtSetSystemInformation(SystemMemoryListInformation=80)`，命令2为全局工作集、命令4为 standby。操作没有指定业务 PID，不能借此声称保护了某个实验进程。真实接口和权限调整仅在实际显式动作中使用，单元测试必须注入假调用。
## （三）工具实例路径
目标顺序为读取宿主证据 → 确认准入 → 保存状态 → 宿主停止该代次接入并复核 → 释放指定使用者引用 → 最后使用者离开时正常关闭 → 确认退出与重建。

目前停在宿主证据不足。聊天 idle、CPU 为零、年龄较大、执行记录缺席、曾有退订事件都不能补齐准入。也不调用执行中断、伪造 `turn_ended`、手工发信号或修改数据库来替代正常关闭。

# 四、数据契约与异常处理
## （一）观测口径
主机容量使用整数 bytes，展示时换算 GiB，速率以每秒数值表达。缺失值为 `null`，实际测得的0保持0。记录采集开始、结束、来源与 `run_id`，跨接口采样不是原子快照。工作集包含共享页，提交残差是减法估计，均不显示为保证可释放量。

工具实例报告必须按字段显示已知与未知，历史证据另带采样时间和版本。未知所有者、未知共享者和未知请求数不转换为空集合。有限的正向执行记录可以证明某实例正在使用，目录为空不能证明所有连接均空闲。
## （二）Windows 动作结果
以下为目标结果语义，字段命名在实际修复时沿用现有结构，不额外引入协议层：

| **结果维度** | **必须表达的内容** | **与现有字段的关系** |
| --- | --- | --- |
| 是否发生动作 | 未开始、已调用或结果未知 | `cleanup_performed` 当前只覆盖至少一项成功，不足以独立表达全部情况 |
| 机制是否完整成功 | 逐项 NTSTATUS、错误及未执行原因 | 复用 `actions`，第一项失败时停止后续项 |
| 观测是否完整 | 前后快照成功或失败、各自错误 | 后快照失败保留动作事实，不重写为操作前失败 |
| 特权是否恢复 | 之前状态、工具是否启用、恢复成功或失败 | 复用 `privilege_scope`，恢复失败不能当作完整成功 |
| 是否有收益 | 未验证、数据不足、仅数值变化、存在代价或支持收益 | 由独立对照分析给出，不能由动作成功直接生成 |

调用前查询与记录不可用时停止。已开始调用后的错误必须保留“可能或确实发生动作”，禁止自动重试。NTSTATUS 不明、日志失败或恢复失败均停止后续动作，保留证据，不升级为更激进机制。
## （三）宿主最小证据契约
下表是对宿主能力的要求，不是已存在的 API 名称，也不据此新增本地注册表。

| **证据** | **最小内容** | **缺失处理** |
| --- | --- | --- |
| 稳定身份 | 实例ID、连接ID、代次、PID及精确创建时间 | 仅作身份线索，保留实例 |
| 全部引用 | owner、全部 consumer、订阅与最终引用释放状态 | 不能证明独占或无人使用 |
| 完整使用状态 | 活跃、排队、挂起、待返回、审批及用户输入等待 | 不能将未观测到视为空 |
| 保存与恢复 | 持久化完成、可丢弃状态及重建约定 | 保存失败或不可重建则保留 |
| 原子提交条件 | 预期代次、状态修订与停止接入边界 | 预检失效时拒绝释放 |
| 完成确认 | 引用释放、连接关闭、目标进程身份退出或保留原因 | 超时与结果未知停止，不升级强杀 |

必须由持有连接的一侧提供。公共 App Server 的聊天退订和服务列表不能自动满足整张表，适用性见通用调研第三章。
## （四）共享与竞争状态
| **状态** | **宿主允许的处理** | **完成判据** |
| --- | --- | --- |
| 证据不足 | 返回保留原因 | 没有关闭动作，未知字段可追溯 |
| 尚有其它使用者 | 只释放本使用者引用 | 连接继续可用，业务不受影响 |
| 可预检 | 固定身份、代次、状态修订并检查保存 | 预检通过仍不等于可以绕过提交时复核 |
| 正在停止接入 | 宿主阻止或排队新请求，再复核状态 | 新请求竞争或代次变化时拒绝本次关闭 |
| 正常关闭中 | 执行 transport 正常关闭并等待确认 | 不能把已发送请求当作已退出 |
| 已关闭或需保留 | 返回退出身份确认或失败、超时原因 | 记录明确结果，按契约验证重建 |

这些状态服务于验收，不引入外部强杀控制器。具体协调实现归宿主，不能让 Python 轮询两次 PID 承担宿主原子性。

# 五、验证设计
## （一）Windows 收益验证
先完成错误记录与部分成功处理的修复，再考虑新实验。每次固定 Windows 构建、权限、负载、采样时间和机制，保留原始输出。实验负载还需同步吞吐、延迟与恢复时间，历史桌面实验不能代替。

沿用可解释的 A/A 与 A/B：A/A 衡量自然波动，A/B 的 B窗前只执行一次指定机制。既有默认计划 `AA,AB,AA,AB`，每窗30拍、间隔10秒，是桌面历史方法，不是所有负载的固定方案。

现有比较器使用0.5 GiB的提交下降或可用尾段中位数增益，以及 A均值×1.5加绝对底数的速率突发规则，再对照 A/A 超限比例。绝对底数分别为5次页面读/秒、50页/秒、5 MiB磁盘读/秒。阈值仍属提案，写盘目前仅观察，不能宣称已包含完整性能门禁。

有效收益需要持续容量改善和无明显工作负载代价。缺指标、窗口不完整、机制部分失败或权限恢复失败不进入收益通过判定。比较器当前仍允许少量数据或未校准窗口得出结论，报告必须保留原始窗口与校准状态，修复时明确数据完整性准入。
## （二）工具实例最小验证
1. 先取得宿主证据契约，固定无业务状态、可重建的独占测试实例，记录同代次的旁路实例状态
2. 人为保留可控待处理请求，验证关闭被拒绝。让新请求与停止接入竞争，验证拒绝或排队符合契约
3. 保存完成、请求结束且引用可释放后，只通过正常入口关闭一次，记录请求、确认、连接移除与原身份退出
4. 重建测试实例，检查文件产物、已约定的内存状态、工具重新初始化与旁路实例可用性
5. 任一结果未知、超时或保存失败时停止，保留实例或原始结果，不自动重试或强杀

该计划未执行。未取得宿主接口前只能验收证据清单和缺口说明，不能交付可用退出脚本。
## （三）测试成本与范围
依照 DreamSoul 测试规范，优先检查失败分支、真实输入边界和持久化边界，不以测试数量替代质量结论。释放、权限和宿主适配的逻辑检查使用替身，真实 Windows 采样与 GUI 属于需明确环境的验证范围。

现有全量测试包含真实单拍 CIM 采样，不在本轮文档任务中运行。新逻辑若后续实施，应针对一项主要契约形成可定位的测试信号，并持久化独立结果。测试目录与标签治理属于后续代码任务，不在本轮顺带重构。

# 六、实施差距与最小推进顺序
| **顺序** | **问题或前提** | **最小完成范围** | **验收信号** |
| --- | --- | --- | --- |
| 1 | 失败被误报为未动作，部分成功冒充整体成功 | 修复共享释放与调用方结果判断，保留后置错误和权限恢复结果 | 假调用下逐项失败停止，执行事实不丢失 |
| 2 | 释放后才发现记录不可写 | 复用现有输出结构，预先打开并保留动作意图，执行后写真实结果，写失败停止 | 不可写、部分写、进程中断各自可识别 |
| 3 | 未来可能重复或并发释放 | 真实需要继续实验时，明确单次互斥与冷却归属 | 多个入口不能绕过同一限制，数值由验证决定 |
| 4 | 宿主所有权及正常关闭能力不足 | 先交付契约核对结果，能力取得后才开发最小适配 | 能力不足明确保留，不出现按 PID 自动关闭 |
| 5 | 目标构建与真实实验负载未验证 | 在另获授权的测试场景验证单机制及恢复 | 原始结果、环境、对照、旁路影响可追溯 |

当前 A/B 用 `tree-series*.jsonl` 最近180秒写入时间推测是否有相关采样。这是启发式，不能证明所有采样停止，也不能替代跨进程动作互斥。GUI 只禁用本窗口按钮，未提供全局冷却。

实施状态：上述逻辑修复、依赖变更、在线清理和退出实验均未开展。架构变化需在实际实施后更新“已实现”状态。
