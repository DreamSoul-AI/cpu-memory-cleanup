# 一、需求与架构目标

用户需要查看真实内存、明确请求一次工作集整理并核对本次变化。主线参考360的软件小助手；不强制先诊断、不结束应用、不以动画替代实际清理。人和Agent共用同一能力。优先保证真实事实、单次派发、界面可响应和资源收尾，再缩小主通道开销。

当前交付是单机回环工作台与命令工具，不建设云服务、插件平台或通用任务总线。操作系统能力由实际接入报告；当前已实现一个平台，其他平台明确不支持，不能补合成值。历史独立窗口及辅助分析不属于当前正式入口。

# 三、真实整理流程

```mermaid
sequenceDiagram
    actor U as 用户或授权宿主
    participant I as 交互
    participant F as 共用功能
    participant S as 系统能力
    participant R as 本地记录
    U->>I: 明确请求一轮整理
    I->>I: 绘制忙碌反馈
    I->>F: 校验请求、确认与范围
    F->>F: 取得维护互斥
    F->>S: 读取前置快照
    F->>R: 保存动作意图
    alt 意图保存失败
      F-->>I: 未派发与具体错误
    else 可以执行
      F->>S: 一轮枚举或固定目标逐项整理
      S->>S: 核验身份、调用、关闭句柄
      S-->>F: 原始返回、覆盖与收尾事实
      F->>R: 保存动作事实
      F->>S: 读取后置快照
      F->>R: 封存报告
      F-->>I: 立即返回摘要和完整报告入口
    end
    F->>F: 释放维护互斥
```

一轮整理包含多个可访问目标的原生调用，不是反复清到某个占用百分比。全局逐项路径不应用保护名单；选定批次使用固定身份及保护快照。取消只阻止尚未派发的后续项，不撤销当前系统调用；调用未知、资源关闭未确认时停止，不重试或换策略。当前没有跨进程全机互斥，只保证本实例内串行；CLI与网页两个独立实例不得由宿主并发发维护。

# 四、读取、结果与动效的三个状态

1. **实时状态**：页面可见时周期只读，维护期间仍可独立请求；实际容量、提交量与时间更新。隐藏或暂停只影响显示请求，不撤销业务。
2. **本次结果**：业务前后真实快照、逐项目标返回及记录状态。一旦就绪立即呈现，不被后续实时读数覆盖，也不等动画结束。
3. **视觉状态**：业务正常结束后下降归零，到零请求一次新读数，得到有效值后回弹，再接回实时显示。无额外趋稳等待；失败保留最后有效值及错误，不补零或重派发维护。新一轮请求取消旧视觉周期，旧刷新不能完成新动画。

```mermaid
stateDiagram-v2
    [*] --> 实际显示
    实际显示 --> 后台整理: 用户点击
    后台整理 --> 结果立即就绪: 本轮执行与收尾结束
    结果立即就绪 --> 下降归零: 正常结束且启用动效
    下降归零 --> 单次只读刷新: 到零
    单次只读刷新 --> 回弹: 有效新读数
    回弹 --> 实际显示: 视觉结束
    单次只读刷新 --> 实际显示: 读取失败并保留错误
    后台整理 --> 实际显示: 异常结果保留
    结果立即就绪 --> 实际显示: 关闭动效
```

动效阶段名不是内存清理进度。业务按钮由任务互斥控制，视觉流程不延长业务忙碌。摘要主通道省略逐项大明细，用户展开原始报告时才读取和格式化完整事实，二者不能各算一份收益。

# 五、部署、规则与质量边界

同一原生程序提供库、命令和回环服务。网页静态资源随程序交付；服务不调用另一份解释器或清理子进程。服务启动、静态工具发现及库构造不采样，只有明确读取或维护请求访问系统。会话令牌、同源校验、回环监听和请求预算限制入口；它们不代替宿主授权。

自动规则为显式可选能力，默认关闭，重启不自动启用。启用时固定目标与保护，持续压力/冷却限制派发；非完整结果停用而不重试。本轮真实验收不启用规则，不能用隔离测试声称实机规则效果。

结果必须分开表达成功、局部限制、失败、未知和取消。完整遍历有成功目标、无未知、资源关闭且两份快照齐备时，可在主区显示“已整理＋真实容量变化”，已知未处理项进入详情；原始partial和错误码不改写。记录缺口、读取缺口、未知或收尾问题仍显著呈现。

# 七、本轮显示与计时职责调整
本节承接开发计划UX-01/02与NATIVE-01，设计先行，本轮已完成实现、隔离检查和真实只读页面验收。原生最小权限和两路并发候选不在本轮，正式串行清理方法不变。

## （一）单一显示驱动
原始快照、业务报告、显示比例分别拥有独立状态。真实读取采用可见页面约250毫秒的轻量请求，至多一份在途，记录实际请求起点间隔和往返耗时，不因系统繁忙补发积压。原始实际百分比、容量与样本时间立即采用最新有效快照，业务结果继续只用本次原始前后样本。

圆环、大号百分比与细条由一个显示驱动、一个绘制循环控制。通常按实际时间连续追向最新真实目标，不每次从零速度重启固定缓动。整理结束后显示驱动按原下降、刷新、固定目标回弹流程播放，后台读数只更新真实目标。回弹结束从已画位置连续接回最新真实值，不直接跳值。隐藏或暂停停止绘制/读取，重新显示从最后显示位置续接。减少动态效果偏好下直接显示真实值。

主操作只更新忙碌状态和必要控件。进程列表不因主操作开始/结束重建，列表重建由发现、筛选、排序、分组或保护变化触发。业务报告一旦就绪立即呈现，不等视觉结束。

## （二）分段测量与完整结果
系统管理记录枚举、打开、身份/路径核验、原生调用、选定目标工作集核验、关闭与其余记账时长；逐项调用分布覆盖全部尝试，明细截断不能默认为完整分布。功能层记录前后快照、意图/动作/最终报告保存等时段。嵌套时段明确包含关系，不相加当墙钟。

报告先记录封存前计时，最终报告写入完成后取得完整业务墙钟及最终写入时间，以同一运行身份的独立计时附件保存，解决记录不能包含自身最终写入耗时的问题。附件失败单列诊断错误，保留既有动作与报告，不重试维护。回看只合并身份和版本相符的计时附件；旧记录可从有界逐项事实计算已覆盖分布，缺失阶段保持未知，不能补零冒充实测。

本轮以隔离系统调用、既有真实原件回放和内置浏览器真实只读状态验收。没有新的真实整理证据，不据本轮界面流畅度或离线计时宣称底层清理已提速。
