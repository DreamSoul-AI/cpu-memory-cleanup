# CPU 内存清理 优化实施计划

执行方式：主代理负责测试执行器与集成，子代理负责独立模块修复和交叉评审。

**目标：** 修复已复现的资源收尾、取消终态、记录归属、指标质量和比较口径问题，保留已有行为与验证证据。

**实现约束：** 沿用当前三层模块和标准库。每项修改落实到拥有状态的现有模块，不新增运行服务或通用框架。

**技术范围：** Python 3.10+、unittest、ctypes。系统故障均用假接入注入。

**依据：** [项目约定](../../../AGENTS.md)、[测试说明](../../../tests/README.md)、[架构设计](../../CPU%20内存清理%20架构设计.md)。

## 全局约束
- 保留上一轮未提交修改；不运行真实维护、不结束业务进程、不修改系统配置。
- 异常收尾不能丢弃已有断言、度量和动作事实；未知不记为零或成功。
- 每项先以最小输入复现，再修复，再验证；新用例登记唯一清单，整体验证集中运行。
- 原始证据保存到新的 `.test-results/optimization-20261023/` 子目录，历史回执不改写。

## 评审重点
- 关闭失败仍尝试收回自身工作进程树，保留失败句柄与已取得结果。
- 中断不被收尾异常替代，收尾失败不能被计为质量通过。
- 终态封存后不再接受无法兑现的取消，收尾期间不允许新请求重入。
- 回看中 header、sample、analysis、end 的归属与顺序相互一致。
- 持续不可用指标每拍保留缺口，正常未知首拍不误判为零。
