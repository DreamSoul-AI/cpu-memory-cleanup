# 三、下一轮先把百分比和点击做顺
依据 [通用调研第十八章](<通用调研 General Research CPU 内存清理.md#十八三秒整理与百分比顿挫的分开定位>)，先解决已能从源码确认的停走、二次过渡和接回跳变，再比较实际原生速度。目标是日常使用顺畅，不增加功能菜单、框架或故障补丁清单。下面是待实施任务，当前没有改成已完成。

## （一）UX-01 统一百分比的显示节奏
- 一个显示驱动拥有圆环、数字和细条。原始快照单独保留，业务报告继续使用原始前后值，不从插值取结果
- 去除JS逐帧width加CSS transition的重复平滑，只有一处决定显示值。数字仅在显示文本变化时写入，使用等宽数字并固定占位，避免位数变化挤动布局
- 真实只读刷新以250毫秒为初始候选，不重叠发请求，隐藏/暂停时停止；实际间隔和请求成本要测，不保证系统忙时固定4Hz。显示按时间连续追踪最新有效值，不每次都从零速度重启400毫秒过渡
- 回弹继续到本次零位刷新取得的真实目标，再从当前显示位置连续接向最新读数，不调用一次直接跳值来切换所有权。旧周期不能接管新周期

验收：离线使用既有真实读数序列覆盖明显下降和回升，核对数据、即时结果与单次派发不变；内置浏览器只读观察真实数值，保存请求间隔、帧间隔分布和衔接记录。没有新数据时允许保持最后有效值，不编造变化。先保持750毫秒下降和300毫秒回弹作为基线，若整数跳步仍明显，再单独比较按位移调节回弹时长的显示候选，不延迟业务结果或零位刷新。

## （二）UX-02 让主按钮与结果不被列表重绘拖住
- 移除主操作开始和结束时无条件重建全部进程行。忙碌状态更新按钮与必要控件，列表只在发现、筛选、排序或分组确有变化时重建
- 保持主区摘要即时呈现、完整报告按需打开。圆环与数字共享显示值，业务状态、真实快照和视觉状态仍分别管理
- 对实际有布局/绘制成本的细条优先评估transform，对渐变圆环及脉冲先测再决定是否换绘制方式，不先引入另一套前端或盲加图层

验收：比较未读列表、已读完整列表且详情折叠、列表展开三种页面状态的点击首帧和DOM工作量；整理相关流程用既有真实报告离线检查，不触发真实动作。正式浏览器使用真实只读状态确认页面和选择入口，不能把离线回放当成新清理效果。基线点击后约21.7毫秒提交只对应当次已筛选列表，不代表完整693项时同样快。

# 四、下一轮把原生长尾测清并贴近360路径

## （一）NATIVE-01 补足一次整理的速度解释
- 正式报告直接给出枚举、访问/身份、原生调用、关闭、快照与记录等互不混淆的时段，并给出P50/P95/P99、最慢目标及其占比。不在主按钮执行期间额外读取每个目标工作集或名称
- 低开销逐项证据沿当前句柄保存身份和时长。分析已有ed4c5691记录作为回归原件，不把后来同号PID名称补成当时进程
- 分开业务墙钟、原生调用合计、浏览器收到结果和视觉结束。当前3.23秒业务中原生3.21秒，最慢20项占48.25%；优化必须对应这个分布，不再以“换语言”作为原因或成果

验收：已有记录的原生总和3211.3656毫秒、业务3231.0558毫秒及分位数能够重算，原件哈希不变。阶段相加只适用于互斥区间；数据缺失保留未知。记录/格式化移出主通道的优化不删除动作前意图和必要收尾，也不许把尚未完成的清理显示成功。

## （二）NATIVE-02 设计与360一致的全局最小权限串行候选
- 拆清全局与明确目标的需求。研究全局一轮是否只需SET_QUOTA并持有当前句柄，减少QUERY与不必要身份读取；定向/批次仍保留PID加创建身份、可选路径及保护快照核验
- 实现前更新架构的身份/覆盖合同和代码结构映射，明确全局记录可能缺少创建时间、可访问覆盖可能变化。仍核对每项返回和关闭，记录跳过、失败和未知，不照抄360未检查BOOL的省略
- 枚举方式仅在有成本证据时比较Toolhelp与EnumProcesses，不为看起来相同先换接口。不转NT、不追加缓存清理，不以减少目标数换速度

验收：先以隔离系统调用检查两类权限、一次调用和资源所有权。当前业务取时窗内的非原生开销只有19.69毫秒，此候选不预设能节省两秒，也不先替换绿色按钮。真实速度与覆盖比较另需明确授权。

## （三）NATIVE-03 有条件准备两路并发对照
这是条件候选，不是已采用架构。只有串行长尾与同范围候选仍不足时，才准备内部最多2个目标并发的装配。360已追到的路径为串行，此项是性能探索，不称为复刻证据，不增加用户侧模式选项。

对照须同一固定负载、同目标与可比起点，分别记录原生墙钟、调用时间合计、完整业务墙钟、成功/失败/跳过及前后容量，另看后续响应代价。所有已派发项完成并关闭资源后才能取后置快照，取消不撤销在途调用，未知不重试。总和可能大于墙钟，不再用“原生合计/业务墙钟”当耗时占比。覆盖下降、返回提前或争用变差都不能当改进。

本轮只登记方法与判据，不运行任何对照，不批准清理自己的测试负载或其他应用。没有可比真实证据前继续串行默认，不保证并发会更快。

# 五、实施顺序与采用边界
1. 先按UX-01/02和NATIVE-01更新受影响架构与代码结构，再实施显示与测量。动作仍一次，结果仍真实立即公布
2. 完成离线真实记录回放、必要隔离检查和内置浏览器真实只读验收，保存本地提交。不将假数据演示当正式验收，不自动点击清理
3. NATIVE-02先完成全局/定向合同设计及隔离实现，NATIVE-03仅条件性准备。真实比较、360动态计时或重复清理必须另有明确范围，本计划不产生运行授权
4. 采用根据同范围业务耗时、覆盖和后续响应判断，不能只看动效、百分比下降幅度或函数返回完成。当前没有证据承诺低于1秒或达到360同速

本轮实际完成的是源码与既有原件复核、调研和计划更新，见 [速度与百分比复核](<运行记录 Run Record/2026-11-02 Rust速度与百分比复核.md>)。所有UX/NATIVE任务仍待实施。定向/批次实机、自动规则、其他Windows版本、Linux、AI资源Agent及发布继续后置。当前0.4.0仍为本地候选，本轮不push、不发布，不修改共用研发用AGENTS。
